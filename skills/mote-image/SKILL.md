# mote 图片创作

把用户的创作意图转成合适的提示词与真实生成参数，用 `mote_image` 生成，结果直接呈现在聊天中。

## 理解与补全

- 用户要求生成或改图时，直接完成创作。只要求提示词、方案或比较时，只给方案，不提交生成。仅在主体、必需素材或互相冲突的硬要求无法合理确定时澄清。
- 保留用户指定的主体、数量、品牌、风格、尺寸和需要出现的文字。引号内的画面文字逐字保留，不翻译或添加其他文案。用户说“原样提示词”时原样使用。
- 信息简略时，补充能服务用途的构图、视角、场景、光线、色彩、材质与视觉层次；版式为标题或其他内容留出合适位置。补充应具体、相互一致，避免堆砌质量词或加入用户没有要求的品牌与水印。

## 选择参数

先调用 `mote_models`，`category` 为 `image`。以返回的目录为准，优先使用配置的默认模型；当默认模型无法满足参考图、尺寸等要求时，选择匹配能力的可用模型。始终提交明确的渠道 ID 和完整模型 ID，同名模型按渠道区分。

用户明确指定的参数优先。未指定时，根据用途自行选择并简短说明：

| 用途 | 比例与精细度的选择依据 |
| --- | --- |
| 头像、图标、简单概念草图 | 通常 1:1；优先满足展示需要的较低档位 |
| 手机壁纸、竖屏封面 | 通常 9:16，重视主体和裁切安全区 |
| 横向封面、风景、演示配图 | 通常 16:9，重视横向构图和留白 |
| 海报、产品展示 | 常用 3:4 或 1:1；依版式、细节和文字需求选档位 |

常规成图可优先考虑 2K；只有用途、复杂细节或用户要求需要时才提高档位。每个选择都必须落在目录声明的枚举、范围和参考素材能力内，不能把这些示例当作所有模型都支持的固定参数。模型接受像素 `size` 时使用其支持的尺寸；`size` 与 `aspect_ratio` 二选一。

`mote_image.n` 表示插件创建的独立单图任务数，默认 1，范围 1–15。选 N 张就调用 N 次上游生成，每次固定 `n=1`；该数量独立于模型目录中的单次出图上限，单图型号也能创建多个独立任务。

用户需要相同要求的多张图片时，用一次 `mote_image` 调用传入 `n=N`。各张需要不同场景、文案或参数时，分别用 `n=1` 提交各自的提示词；所有调用的总任务数须符合用户要求。插件采用独立单图生成，不启用关联组图。

分辨率、比例与独立任务数通过工具参数提交，不用在提示词里写“4K”冒充真实分辨率设置。参考图只使用用户提供或前一结果返回的有效图片 URL / 平台文件标识；每个单图任务遵守模型参考图角色与数量限制。

## 生成与交付

1. 将补全后的画面描述放入 `prompt`，原始用户要求放入 `original_prompt`，并传入选定的 `model`、`channel`、比例 / 尺寸、分辨率和独立任务数。提示词、参数和渠道确定后调用 `mote_image`；无需为合理的默认选择反复征求确认。
2. 单图返回一个 `submissionId`；多图在 `results` 中逐条返回独立的 `submissionId` 和状态。逐条用 `mote_media_task`（`action: status`，`submission_id` 填该条的 `submissionId`）查询未完成任务，完成后自动保存产物。一张失败不影响其他任务；结果待核实、超时或中断时恢复已有记录，只有用户明确要求继续创作或重新生成时才增加任务。
3. 图片已生成而保存失败时，只重试下载，不重新生成。交付以实际任务状态和产物为准；简短说明所选模型、比例 / 分辨率与必要的选择理由，聊天媒体卡保留优化后的提示词和参数供查看。

后续“改成夜景”“保留构图换颜色”等请求，结合上文的实际图片和用户修改点组织编辑提示词，并选择支持参考图的模型。保持未要求修改的主体、内容和风格；只讨论改法时仍只提供方案。
