# 生成与作品流程修复

范围：防重复提交、完整输入快照、多产物、渠道与模型联合选择、下载结果反馈。

实现约束：

- 继续使用 DSH 提供的 React、现有认证 Host 路由、两个渠道驱动。
- 生成前通过 `prepare` 保存完整输入和固定 `submissionId`，再以该 ID 调用 `generate`。浏览器在付费提交前保存轻量任务记录。
- Host 在包根目录 `.mote-submissions/` 持久化快照和任务收据，使用独占提交标记；同一 ID 不再次创建上游任务。目录从 Git 和运行包排除。
- `submission` / `submissions` 只恢复查询；提交结果未知时不重发。明确区分继续尚未提交的任务、恢复查询、以新 ID 重新生成。
- 两个驱动的生成 POST 不自动重试。Mote 仍携带固定上游幂等键，但本批不依赖无法在线核实的上游幂等重放保证。
- 新任务快照包含类型、渠道、模型、提示词、参数及全部参考素材角色/来源。旧任务缺少完整快照时提示重新编辑，不静默退化为纯文本生成。
- 新模型选择使用渠道和模型联合标识；多产物按实际数组位置选择，视频封面/尾帧不单独成为输出作品。
- 下载按所选产物执行并分别报告成功/失败；旧请求仍可下载整项任务。

验证入口：沿用已确认的公开 Host 路由、模拟上游和 React 页面。覆盖提交去重/响应丢失/Host 重启、快照重放、同名模型、多张立即或轮询完成、部分下载失败。真实 DSH 仅做非付费页面验证。

## 本批行为与兼容性

- 新增 `src/host/media/submissions.js`，在包根目录保存独立快照/收据及独占提交标记。输入冲突会被拒绝；正在处理和未知的旧尝试都不会再次执行生成。
- `generate` 面板 action 改为要求已准备的 `submissionId`，拒绝缺少标识的旧请求；四个工具名称、mote 兼容导出及媒体方法保持可用。
- 新增可选默认渠道配置 `imageChannelId`、`videoChannelId`。同名模型不再隐式选择第一个渠道；创作台与设置中的选择都包含渠道。
- 原浏览器存储键保留，新记录为轻量元数据。输入快照由 Host 提供，配额失败在生成前显式阻止提交。
- 作品列表同时处理同步成功与轮询成功，按主产物拆分并修正预览/复用/下载；删除单张后不会在下次更新中重新出现。
- 下载检查真实文件与目标路径，读取、复制和写入失败均保留逐项错误，不按返回数组长度冒充成功。

## 验证与边界

生成及异常场景全部使用模拟上游、临时目录和 React DOM，未提交真实付费生成。覆盖并发重复调用、丢失响应、未知 500、Host 在途重载、快照及首尾帧恢复、局部文件参考的字节保存、同名模型、配额不足、重复点击、立即/轮询多产物、部分下载和文件写入失败。

2026-10-28 验证结果：`npm run build`、`npm run verify` 和 `git diff --check` 通过，共 66 项测试；真实 npm 安装包包含 27 个运行文件，解包后的 Host 与客户端入口可加载，未新增运行时依赖。

在本机现有 DSH 目录安装中重载后，客户端显示已连接和带渠道名的模型选择，已有 5 条作品仍可读取。预览旧作品可看到缺失完整输入的提示；未保存渠道配置、删除作品或点击生成。此页面检查不等同于真实 Provider 的付费生成验收。

该机制防止插件对同一提交标识重新发起生成，不承诺上游内部的处理/扣费行为。无任务收据的未知结果需要核实；旧作品缺失的输入无法重建。当前浏览器作品列表仍保留 120 条上限，本批不实现跨设备作品库。
