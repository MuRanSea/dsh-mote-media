# 下拉菜单方向与长列表修复

日期：2026-10-28。

用户现象：模型菜单经常向上展开，选项多时弹层过长，遮挡提示词和页面内容。

原因：原方向判断在上方空间达到 200 px 时便选择向上，不要求下方空间不足；高度上限为 360 px，并强制保留至少 140 px，缺少垂直面板边界约束。长模型 ID 还会换行增加单项高度。

修复：

- 默认向下；下方不足以显示一个可用菜单、且上方空间更多时才翻转。下方还有 140 px 等短空间时，保留较短的下拉菜单。
- 高度上限为 260 CSS px，同时不超过面板可用高度的 40% 和所选方向的剩余空间；去掉强制最小高度。横向与纵向都限制在面板 / 视口内。
- 模型菜单新增固定搜索栏，可组合搜索名称、完整模型 ID 和渠道分组；空分组自动隐藏，无匹配时有明确提示。模型与渠道的联合选择值不变。
- 仅选项列表内部滚动；长名称和 ID 单行省略，通过悬浮提示查看完整内容。键盘方向键选择、Enter 确认和 Escape 返回保持可用，聚焦不滚动外部页面。

验证：

- 修复前运行 `node --test --test-name-pattern="long model menu opens" tests/ui-components.test.mjs` 两次，均在“下方有空间却向上展开”断言失败。
- 新增回归覆盖普通下拉、可用空间较短时下拉、靠近面板底部时向上避让、面板边界、内部滚动不关闭、名称 / ID / 渠道搜索、分组、无结果、键盘与原始联合值。
- `npm run build`、`npm run verify`、`git diff --check` 通过，共 **81 项测试全部通过**。真实 npm 包仍包含 **27 个运行文件**，解包后的 Host / 客户端入口可加载。
- 隔离预览 `?models=long` 提供 23 个模拟模型：桌面实际弹层高度 260 px，位于触发按钮下方，列表可滚动；搜索 `banana` 后为对应渠道的 4 项结果。400 px 面板中弹层完整落在面板内，仍向下展开，无横向越界。
- 隔离预览中搜索长模型 ID 后按 Enter，可选择正确模型并关闭菜单。真实 DSH 中向下展开与限高生效，搜索 `banana` 显示原渠道的 4 个 Nano Banana 结果，Escape 关闭后当前模型未改变；未触发生成或保存配置。

生成协议与 Host 未修改。测试和隔离预览不调用真实生成服务。
